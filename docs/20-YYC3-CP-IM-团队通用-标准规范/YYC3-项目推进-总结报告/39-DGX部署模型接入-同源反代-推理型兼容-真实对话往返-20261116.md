## 一、DGX 模型画像（直探实证）

| 项 | 值 |
| ---- | ---- |
| 端点 | `http://100.65.64.49:8888/v1`（vLLM OpenAI 兼容） |
| 模型 | `nemotron-3.5-super-vl`（`owned_by: vllm` · max_model_len 1048576） |
| 特征 | **推理型模型**——`content` 为空、答案在 `reasoning` 字段（/no_think、chat_template_kwargs 均无法关闭思维链） |
| 推理延迟 | 首字 ~2s（vLLM warm）；2048 tokens 完成 ~8s |

## 二、接入三补丁（本批产出）

### 1. 推理型兼容（`4252f19` · family-ai-service）

```ts
// content 空 && reasoning 有值 → 取末段 400 字（结论在尾）作为回复
const reasoning = choice?.message?.reasoning?.trim() || "";
if (reasoning) { return { text: reasoning.slice(-400), success: true }; }
// max_tokens 500→2048 / timeout 30s→60s
```

### 2. 同源 CORS 反代（`8e9d2f5` · deploy/server.mjs）

浏览器直连 vLLM 被 CORS 拒（引擎诊断实证）→ `server.mjs` 镜像 Ollama 块新增：
```
/api/v1/llm/dgx/* → PMO_DGX_URL（默认 100.65.64.49:8888）/ *
```
curl 实测 200；CSP 无需改（同源路径）。

### 3. 引擎代理超时对齐（`8e9d2f5` · connection-test-engine）

CORS 代理通道步 12s→45s（DGX 级首字延迟可超 12s）。**已知遗留**：引擎以 `provider.baseUrl` 构造绝对 URL 导致代理步 URL 拼接双重前缀（`proxy/http://…`），非 2xx 即报"代理不可达"——实际链路（family-ai-service `buildChatUrl` 用 `cm.baseUrl` 相对段 + `proxyUrl` 绝对段）**不受影响**。登记 P6 后续：引擎改用 cm.baseUrl。
