## 三、与文档日志体系的衔接规则（自本档起生效）

1. **双轨定位**：本目录 = 落档轨（阶段成果，编号严格递增，**下一个编号 23**）；`0307-CP-IM-开发进度/logs/` = 会话轨（每次会话四件套）；根 CHANGELOG = 版本轨。006-总纲为制度权威。
2. **命名去歧义**：两轨存在同名文件（`00-项目现状审核报告.md`），以目录区分语义——落档轨编号版为「对外序列」，会话轨四件套为「过程记录」；互引时必须带目录路径。
3. **schema 统一路径**：落档 23 起新落档采用 006-总纲 schema（11 必填字段 + 标尾），存量 21 份**不批量回改**（避免无意义 diff），由 `pnpm docs:check` 逐步覆盖迁移；轻量 schema（title/date/stage/commit/gates）中的 `commit/gates` 字段作为扩展字段保留在 `complexity` 之后。
4. **注册表互链**：`0307-.../registry/doc-log-registry.json` 为追溯中心，跨轨引用写入 `related_docs`（本文档与会话 00-报告已互链）。
5. **在途工作红线执行**：任何源码改动批次结束时必须「提交 + 落档 + 回填 commit 号」三件事齐备；发现未落档的在途改动，下一会话第一件事即补档（本文档 §四 即示范）。
