## 一、结论

**【CP-IM】存储架构有缺陷，且不是个别键的问题，是「没有统一边界」**：

- **29 个 Zustand persist 键 + 40 余个裸 localStorage 键 + 24 个 IndexedDB store**，键名、版本、备份/清空范围各自为政。
- **同一域多套键**：设置（旧 store / SSOT / api-config / env-config）、数据库（三套）、Family 绑定（两套）、provider（新 persist + 两个旧键）。
- **清理用全局 `clear()`**：会抹掉同源其他应用数据，且不清 IDB。
- **备份注释写「脱敏」，代码原样复制**：备份文件含 API Key、密码、会话 token。
- **独立性**：核心监控链可完全本地；但 AI 链默认走 3118 + NAS/DGX 或云 provider；隐藏外联（Google Fonts、GitHub raw 图标、占位图、soundhelix 音频、STUN、WebLLM 权重、外网连通性探测）与「数据不出本地」冲突。

### P0

| # | 缺陷 | 位置 |
| ---- | ---- | ---- |
| P0-1 | 敏感信息明文落 localStorage：`aiApiKey`、`wsToken`、`dbPassword`、provider `apiKey`、family `providerKeys`、WiFi 密码、`secret.*`、Ghost token；至少 6 套键重复保存同类凭据 | `settings-ssot-slice.ts`、`provider-slice.ts`、`family-settings-slice.ts`、`network-slice.ts`、`variable-center.ts`、`mock-auth.ts` |

| P0-3 | 变量中心 `secret.*` 明文存储且无任何消费者（高危死配置） | `variable-center.ts:266-339` |

### P2（摘要）

无版本 persist 9 个；嵌套对象浅合并缺省；IDB 24 store 中多个死表、索引未建；DB 密码加密失败降级 base64；错误日志双写；多数历史表无上限；Family 多数组无上限；跨标签同步覆盖极小；派生数据持久化；`LOCALSTORAGE_KEYS` 常量与实际键不符；同步队列两模块共用同键；离线快照读错键；PWA 全 mock；token 放 URL query；队列无上限；配置解析失败直接删键；备份前缀不对称；Electron DB 备份路径未限制。

## 四、项目独立性评估

| 依赖 | 是否必需 | 可替换性 | 现状 |
| ---- | ---- | ---- | ---- |
| agent `ws://localhost:3113` | 必需（节点/文件/规则） | 可换同协议实现 | 直连，本地 |
| OpsPanel `127.0.0.1:7864` | 默认启用（GPU/温度/历史） | 可换同接口源 | 直连，本地 |
| 3118 本地反代 | 生产必需（静态托管 + CORS/头翻译） | 可换 Nginx | 保留（落档 57 定案） |
| NAS / DGX 上游 | AI 聊天 | 可配 | 私网 IP 为默认，仅 deploy env 可改 |
| 云 provider | 非必需 | 可移除 | 默认注册，需显式配置 Key |
| 0379-World B 端 | 定位 | 低耦合（NAS 网关） | 代码层无共享契约 |
| 文件根 `~/.yyc3-cloud-matrix` | 必需 | 可配 | 写死 |
| Google Fonts / 占位图 / 音频 / STUN / WebLLM | 非必需 | 可本地化 | **隐性外联，与本地自用冲突** |

**结论**：存储与运行时的最大风险不是「缺功能」，而是 **凭据明文、备份泄露、清理越界、设置不生效**；独立性最大漏洞是 **隐性外联资源** 与 **部署路径指向旧仓库**。

## 五、下一步（按风险）

1. 凭据加密：接入 Web Crypto（`crypto-vault`）到 SSOT/provider/family/network；`partialize` 剥离敏感字段；迁移现有明文。
2. 恢复语义：导入前显式确认覆盖、清项目键/IDB 后导入、恢复后 `rehydrate` 或 reload。
3. 统一键：`apiEndpoints`/`variableValues` 只留 SSOT；DB 三套 store 合并；Family 绑定以 member slice 为唯一运行时源。
4. 独立性：字体/占位资源本地化；移除默认外网探测；部署 plist/nginx 路径改为动态。
5. 容量治理：IDB 历史表加上限/TTL；`fs-slice.fileContents` 不入 localStorage；日志单写。
