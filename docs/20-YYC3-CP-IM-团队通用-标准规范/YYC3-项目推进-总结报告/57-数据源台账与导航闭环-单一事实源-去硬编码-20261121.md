## 〇、定位与原则（2026-11-21 主控重申，本文唯一口径）

| # | 原则 | 工程含义 |
| ---- | ---- | ---- |
| 1 | **非商用 · 本地自用 · 数据不出本地** | 数据源限本机 / Tailscale 私网；云端模型仅用户显式添加，不做隐式兜底 |
| 2 | **拒绝一切硬编码** | 地址、端口、路径、模型名、阈值一律进配置；代码只允许「默认值 + 可覆盖」 |
| 3 | **源控在系统管理** | 每个数据源都能在系统管理里增 / 删 / 改 / 测；改完即时生效 |
| 4 | **不做数据转接** | 能直连就直连；必须经本地反代时，反代本身登记为数据源（3118 保留，上游明确） |
| 5 | **按导航分类闭环** | 一个分类 = 源 → 动作 → 回执 → 回读验证，缺一不算闭环 |

**部署场景**：办公地 A / 办公地 B 两套静态 IP 环境 + Tailscale；本机与主控人员两地流转，其余设备 24h 无人值守。项目价值 = **智能化协同中控中心**。

**对外定位**：本项目有意作为 **YYC3-0379-World 的 B 端**（业务侧控制台）；API 对接按 0379-World 契约为准。
**3118 反代**：**保留**——定位为「本地反代数据源」（浏览器 CORS + NAS `X-API-Key` 头翻译），不再视为隐式转接。

## 一、导航闭环盘点结论（53 项）

判定口径：源真实 → 系统管理可配 → 动作真实 → 有回执 → 可回读验证 → 无硬编码/无转接。

| 判定 | 数量 | 代表项与缺口 |
| ---- | ---- | ---- |
| **完整闭环** | **0** | — |
| A 只读/局部真 | 12 | 数据监控（节点写无 agent 回执）、性能监控（导入硬编码 7864）、文件管理（根目录写死）、宿主机文件（根目录不持久化）、连接测试（外网探测硬编码）、数据备份（含明文密钥）、模型管理（默认走 3118）、SDK 对话（Ollama 端点写死）、Family 模型（默认绑定写死）、安全监控、环境变量、配置中心 |
| B 展示真、动作只落本地 | 10 | 一键跟进、协同管理、巡查（阈值写死）、告警规则（下发真、无回读）、服务闭环（execute 只建单）、智能决策、智能诊断（execute 假）、Family 中心、数据总控（半死端）、性能监控（CLS/INP 写死） |
| C 可配置但执行假/随机 | 13 | 操作中心（4 真 8 假）、数据库管理（默认无后端）、连接配置（测试恒随机）、报表（全随机）、系统设置（双源分裂）、统一设置（徽章假）、操作审计（统计假）、用户管理（与登录脱节）、存储管理（模拟连接）、变量中心（无消费者）、Family 设置（自检随机）、主题定制（不生效）、终端（模拟 shell） |
| D 纯 UI/演示/占位 | 18 | 连接监控、PWA、Family 中枢/首页、酒店、通讯基站、8 个规划页、设计系统、开发指南、重构分析、架构审计 |

**结论**：此前所有「推进」都停在「页面能看/能点」，没有一项完成「动作 → 回执 → 回读」闭环。后续以本表为唯一进度口径，逐分类销项。

## 二、数据源台账

| 数据源 | 现状 | 系统管理入口 | 缺口 |
| ---- | ---- | ---- | ---- |
| agent WS（3113） | 直连 | 系统设置 → WebSocket（本轮改为 SSOT，生效） | 协议固定 ws://，不支持 wss |
| OpsPanel（7864） | 直连 | 系统设置 → WebSocket → OpsPanel 地址（生效） | 导入探针曾写死（本轮已改）；子路径写死 |
| Ollama（11434） | 直连 + 3118 代理两套逻辑 | 模型管理 / 环境变量 | chat 端点曾写死 `hostname:11434`（本轮已改） |
| NAS 网关 | 经 3118 反代 | 模型管理（仅前端入口） | 真实上游 `100.65.172.88:8000` 在 deploy env，UI 不可改 |
| DGX vLLM | 经 3118 反代 | 无 | 上游 `100.65.64.49:8888` 在 deploy env；无 UI 入口 |
| 数据库 | 三套 store 互不联通 | 连接配置 / 系统设置（不生效） | `/api/db` 无后端；备份/恢复无回读 |
| 文件系统 | agent `/files` 直连 | 无 | 根目录 `~/.yyc3-cloud-matrix` 写死 |
| 3118 本地反代 | 保留（本轮定位为数据源） | 无 | 上游/监听只可改 env；建议后续登记为可配源 |

## 三、本轮整改（第一批，代码）

| # | 问题 | 改法 | 证据 |
| ---- | ---- | ---- | ---- |
| 1 | 系统设置 WS 四字段写旧 store，实际不生效 | 新建 `WsConnectionFields`，端点/重连间隔/最大次数/心跳间隔/节流全部读写 **Settings SSOT**；`wsAutoReconnect`/`wsHeartbeat` 开关也接 SSOT | `SystemSettings.tsx`；E2E 显示值与 SSOT 一致 |
| 2 | 自动重连/心跳开关无消费者 | `useWebSocketData` 读取开关：关闭自动重连则超限不重试；关闭心跳则不起定时器 | `useWebSocketData.ts` |
| 3 | agent HTTP（文件/规则/健康检查）从 `api-config` 推导，可能与 WS 端点分裂 | 三处改为优先 `SSOT.values.wsEndpoint`，与 WS 实际连接同源 | `agent-rules-sync.ts` / `useLocalFileSystem.ts` / `useOperationCenter.ts` |
| 4 | Ollama chat 端点写死当前主机 11434，忽略 baseUrl | `getOllamaChatUrl(model)` 取 `model.baseUrl`，统一走 OpenAI 兼容 `/v1/chat/completions`（修正 native `/api/chat` 与 choices 解析不一致的潜在缺陷） | `model-request.ts`；curl 实测 `/v1/chat/completions` 200 |
| 5 | 「从 OpsPanel 导入探针节点」写死 7864 | 改用 `SSOT.values.opsPanelBaseUrl` | `DevicePerformance.tsx` |
| 6 | 服务商自定义/编辑刷新后可能被 `migrateProviders()` 覆盖；内置删不掉 | rehydrate 改为「保留已有 + 补齐未删除的内置」；新增 `removedBuiltinIds` tombstone，删除内置后不再自动补回；`resetProvider` 撤销 tombstone；`resetAllProviders` 清空 | `provider-slice.ts` |
| 7 | 空态时凭 `PMO_*_API_KEY` 自动生成云模型 | **本批未改**：按「服务商当前已定即可」保留现状，后续如要严格执行本地优先再议 | — |

## 四、下一步（按原则排序）

1. **数据源注册表（系统管理 → 数据源）**：把 agent / OpsPanel / Ollama / NAS / DGX / DB / FS / 3118 反代统一成可增删改测的源列表，所有 Hook 从注册表取地址；NAS/DGX 上游写入受控配置文件而非 deploy env。
2. **分类闭环顺序**（每类必须补齐回执与回读）：
   - 数据监控：节点增删改 → agent `node_update` 应答（或明确只做本地台账并移除下行）；刷新/周期按钮补齐。
   - 告警闭环：规则下发 → `GET /rules` 回读显示「已生效」→ 告警 → 工单 → 处置 → 指标回读验证。
   - 运维闭环：数据库连接三套 store 合并；`/api/db` 真实后端或明确关闭；备份脱敏/加密。
   - 智能引擎：诊断「执行」接真实动作或明确只读；决策只建单改为派单闭环。
3. **本地优先**：云端模型默认不启用；Family 绑定缺 provider 的 qwen/claude 清理或补齐。
4. **0379-World B 端对接**：以对方 API 契约为准新增数据源条目（不转接、只消费）。

## 五、遗留与风险

- 3118 监听 `0.0.0.0` + CORS `*`：局域网内任意客户端可借道云模型；后续加来源限制/鉴权。
- 全量备份含明文 API Key（`full-backup.ts:82-83` 注释与实现不符）。
- 系统设置仍有大量字段写旧 store 无消费者（AI/DB/集群/告警阈值等），按分类逐步迁移到 SSOT 或删除。
