## 一、背景（落档 51「下一步」兑现）

落档 51 交付会话级时序时登记：「服务端时序存储接入后，把性能监控采样窗口从前端会话级升级为服务端持久——需动 OpsPanel 侧」。本轮闭环。

**升级前**：`metrics._history` 环形 60 点、**仅内存不落盘**、**pull-driven**（浏览器不开就断采）。
**升级后**：服务端自主采样 + 落盘续接（360 点 ≈ 1h），前端启动回填 → 刷新/重开浏览器曲线连续。

## 二、OpsPanel 侧（`ed8000c`，3 文件 +100/-15）

| 项 | 实现 |
| ---- | ---- |
| 窗口 | `HISTORY_MAXLEN` 默认 60 → **360**（10s × 360 ≈ 1h） |
| 采样节流 | `SAMPLE_MIN_INTERVAL = 10.0`：无论调用方是前端轮询还是服务端自主采样，距上次 append < 10s 则跳过——**历史节奏恒定不翻倍** |
| 落盘续接 | `data/metrics_history.json`：原子写（tmp + replace）、30s 节流、启动 `_load_history()` 恢复（文件缺失/损坏从空开始，不阻断启动）——对齐 `probe.HISTORY` 既有模式 |
| 自主采样器 | `lifespan` 新增 `_metrics_sampler()`：10s 周期 `metrics.collect(force=True)`，**浏览器不开也持续生长**；异常只记 stderr 绝不拖垮面板 |
| 退出落盘 | `lifespan` finally 增 `metrics.save_history(force=True)` |
| 新端点 | `GET /api/metrics/history` → `{history, interval_s}`，**纯读不触发采集**，供前端轻量消费 |

**测试**：`test_history_ring_appends` 按新口径重写（节流窗内三连采集仅 1 点 + 回拨 11s 后正常续记）；OpsPanel 全量 **84 用例通过**。

**实测（launchctl 重启后）**：
- `/api/metrics/history` 节奏恒定 **10s**（22→37→45 点持续增长）
- DCGM 双源 `ok`（yyc3-n1/n2），`gpu 0.0% / temp 53°C` 为当前推理空闲真实值
- `data/metrics_history.json` 落盘存在并随采样增长

## 三、前端侧（`d9382b6`，2 文件 +56/-12）

`useNodeTimeSeries` v2.0.0：

- **启动回填**：首消费者挂载时一次性 `GET /api/metrics/history`，把 `{ts, avg_gpu_util, max_gpu_temp}` 映射进环形窗口底部（`hydrated` 标志防重入；失败静默回落纯本地窗口，不阻塞首点）
- **续采**：本地点继续 10s 追加；与本地重叠区间**以本地点为准**（本地含 CPU/内存更完整）
- **诚实口径**：服务端无 CPU/内存来源 → `avgCpu/avgMem = null`（图表断线呈现，不插值不补零）
- **门控一致**：复用 settings SSOT（demoMode / opsPanelEnabled / opsPanelBaseUrl），与其他 OpsPanel 消费端同规则
- `DevicePerformance`：徽标改「服务端持久时序 · 10s 采样 · 环形 60 点」，图例窗口说明与口径脚注同步为「回填 + 续采」

## 五、口径与登记

- **两条时序分工不变**：GPU/温度 = 服务端历史（可跨会话）；CPU/内存 = 前端实时（服务端无来源，历史段如实断线）
- **已知行为（沿袭落档 51）**：重载瞬间 `startSampler` 立即 `tick()` 一次，此时 WS/探针数据尚未到达，会记录一个 0 值点（表现为曲线起点短暂下探）。属既有行为、非本轮引入；如需消除应改为「首帧等数据源就绪」策略，登记备查、本轮不改语义
- **落盘文件不入库**：`data/metrics_history.json` 为运行时产物（OpsPanel 仓 `data/` 既有约定）
- Mimosa 提交钩子报 i18n en-US:844 / zh-CN:842 硬编码凭据——落档 50 已登记的 enterApiKey **文案误报**，本轮未触碰；扫描覆盖不完整不构成安全结论
- 长历史（>1h）仍归 NAS Prometheus 二期
