## 五、评测门禁执行契约（G0~G4，唯一口径）

**契约性质**：本节为所有功能批次收口的强制门禁。执行结果必须回填当批次落档 `gates:` 头或变更历史；任一项 fail → 不提交、不出结项报告，fail 项如实登记。

### G0 质量门禁（静态，每批次必跑）

| 项 | 命令 | 通过线 | 此刻值 |
| ---- | ---- | ---- | ---- |
| 类型 | `npx tsc --noEmit` | 0 错误 | 0 ✓ |
| 测试 | `npx vitest run` | 全绿，禁 skip 伪装 | 280 文件 / 4729 用例 ✓ |
| 构建 | `npm run build` | ✓ | ✓ |
| 文档 | `npm run docs:check` | 0 error | 9 篇 0E ✓ |
| Lint | `npx eslint <本次改动文件>` | 0 error | ✓ |
| 凭据 | 人工+扫描：源码/示例/测试零可用凭据字面量 | 0 命中 | ✓（测试占位值运行时拼接） |

### G1 架构完整性（结构变更时）

1. 新页面四件套齐备：`routes.tsx` + `page-config.ts` + `Sidebar.tsx` + i18n（中英），缺一即 fail。
2. 新增/变更 store 必须入 `storage-registry` 审计口径（键名 `yyc3_`/`yyc3-` 前缀、备份白名单、清理白名单），并在落档登记 IDB/persist 归属。
3. 唯一编辑面纪律：模型与 Key 只在「模型管理」；连接源只在「数据源」；禁止出现第二套平行编辑面（落档 65 裁定）。
4. 新增外联目标（任何新 host/端口）必须先入数据源注册表并过私网校验，禁止绕过。

### G2 数据链路真实性（每条新/改链路）

1. 四元组登记：源 → 路径 → 消费方 → 断链语义（写进当批次落档，格式同本档 §三）。
2. 断链必须可观测：空态文案或语义化错误，**禁止**以 0、随机值、模拟数据顶替；演示数据只允许 demoMode=true 显式开启。
3. 数值可追溯：面板每个显示值能回答「来自哪个源的哪次采集」（G4 抽查）。
4. 凭据链：凭据只进内存态与加密 persist；代码/文档/日志零明文。

### G3 API 路由可达性（收口前逐条 curl）

1. 以本档 §四 路由表为基准，逐条探测并回填实测码；新路由必须先入表再实现。
2. 预期码语义化：200 正常；401 仅当「网关在·缺凭据」或「令牌门控」；502 仅当上游未启动；404 仅当路由确实不存在——**不得把任一状态码伪装成成功**。
3. `PUT /api/config/sources` 必须验证：公网地址 400、私网地址 200 且落盘。

### G4 真实性抽查（每批次 ≥3 个显示值）

1. 抽查方式：页面取值 → 反查其 hook/slice → 反查采集源 → 与源端原始响应比对，四层一致才算 pass。
2. 空态文案审查：不得出现「数据为模拟值」（demoMode 关闭时）等误导文案；暂无数据必须说明原因（如「vLLM 在线·当前无在途请求」）。
3. 口径一致性：`gpuAvailable/tempAvailable` 门控必须铺满所有消费该字段的卡片（现存缺口见 §六，登记为待收口而非默认通过）。

## 六、契约之上仍开放的工程项（如实挂账，不伪装通过）

1. WS 单实例化未做（落档 56 挂账①）——多组件各自 `useWebSocketData()` 仍会建多条连接。
2. 节点矩阵卡 0 值门控未铺满：无 GPU 证据节点仍显示 `0%`、温度一律 `0°C`（B1 口径未覆盖到该卡）。
3. 温度需 powermetrics 授权；本地 Ollama 无 Prometheus 端点，无真实 QPS/Token。
4. Ollama serve 进程当前挂起（/api/tags 超时）→ 反代 502 如实；需本机侧恢复服务。
5. NAS 链路最后一环：模型管理录 vk 后 L4 全通。
6. 落档 65 工作区改动待主控验收后提交。
