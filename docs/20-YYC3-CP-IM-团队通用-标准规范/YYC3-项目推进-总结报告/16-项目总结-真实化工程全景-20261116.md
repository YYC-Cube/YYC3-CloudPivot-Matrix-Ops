> 本文是 YYC3-Cloud-Matrix 从「演示看板」到「真实可用」改造工程的阶段总结。
> 一切结论以源码与浏览器实证为依据；配套文档：落档 17（未执行项）、18（API 路由）、19（数据架构）、20（演进规划）。

## 一、项目定位（一句话）

**YYC3-Cloud-Matrix 是一个无后端、本地优先的多节点设备/模型部署与算力监控自用平台**：前端 SPA（Vite + React 18 + TS 严格模式）通过本地 `yyc3-agent` 服务（HTTP + WebSocket）采集真实节点指标，通过 OpenAI 兼容协议对接用户自配模型服务，全部业务数据持久化于本地 localStorage，数据不出本机。

## 四、政策红线（全项目有效，违反即回退）

1. **一切数据禁止硬编码**——可编辑项、可增减项尤其；静态定义（角色元数据、勋章定义、分类映射）允许，业务数据不允许。
2. **无后端设计**——localStorage/IndexedDB + yyc3-agent；不引入任何云端依赖（`supabaseClient.ts` 为历史遗留，未接线）。
3. **demoMode 闸门**——演示数据必须挂 `useSettingsSSOT((s) => s.toggles.demoMode)`（默认 false）；demoMode 关 = 真实路径，不可达时**诚实离线/空态**，绝不回退假数据。
4. **数据不出本地**——AI Family 人格、对话、配置全部 localStorage 持久化；模型端点由用户自配（NAS gateway 走自定义服务商，零代码改动）。

## 五、AI Family 真实化架构（落档 15 成果）

```
成员 modelAssignment（member slice = SSOT，模型设置页双写）
  → provider-slice configuredModels 精确匹配（providerId + model）
  → OpenAI 兼容 /chat/completions 真实调用
    · system = 成员 systemPrompt（可编辑）→ 缺省回退曌·中枢三件套（8 份原样导入，原仓只读）
    · 30s 超时 / history 10 条
  → 未绑定/未配置/缺 Key/不可达 → source:"error" 诚实离线（UI 系统胶囊提示）
demoMode 开 → 演示引擎（agent/mock），消息挂「演示」徽标
```

人格编辑入口：`#/ai-family/center` → 展开成员卡片 → 「人格设定」；模型绑定入口：`#/ai-family/models`。
