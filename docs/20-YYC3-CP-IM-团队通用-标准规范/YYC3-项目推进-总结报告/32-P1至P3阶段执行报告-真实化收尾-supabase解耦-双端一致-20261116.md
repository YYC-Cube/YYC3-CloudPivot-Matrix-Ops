## 三、P3 双端一致性 ✅（批6续收口，根因链完整）

**现象**：Web(3118) 探针驱动仅个别节点生效、user 节点一度消失；安装版正常。

**根因链（运行时示踪逐层定位）**：
1. **主因：OpsPanel（FastAPI:7864）无 CORS 中间件** → Web 源（localhost:3118）页内 fetch `Failed to fetch`（fetch 包装探针实锤每轮 REJ；安装版 file:// 的 origin null 此前偶然通过）→ 探针更新落空。
2. **次因：陈旧标签页污染**——旧 bundle 标签页共享同源 localStorage，其旧 merge 代码删除 user 节点后回写，掩盖真实状态（agent clients 一度 8 个）。
3. 排除项（实证记录）：rolldown 缓存（产物 hash 核对无陈旧）、Service Worker（无注册）、mergeFromWS 修复源码（在位且正确）。

**修复**：
- OpsPanel `app.py` 注入 `CORSMiddleware`（allow_origins=*，GET only；服务回环绑定，安全性可控；属本集成数据源服务的配套改动）+ `launchctl kickstart com.yyc3.panelv2` 重启 → `access-control-allow-origin: *` 生效。
- 关闭陈旧标签页；hook 临时逐节点 trace 示踪后移除（保留单行 dbg 心跳）。

**终态实证（Web 版，最新 dist）**：`7/7 活跃节点`（DOM 实时态）· trace 七节点逐一 updateNode 命中 · 已连接 · 无模拟值 · 截图 ×2 存档（P3-Web版-CORS修复后-双端一致性达成.png 等）。**与安装版（批6 全 active）双端一致。**
