## 二、C-1：WS 单实例化（落档 56 挂账① 清账）

**改前**：`useWebSocketData()` 每个消费者各自持有 `wsRef` 建独立连接——Layout / 告警规则 / 一键跟进 / 巡查 / AI 诊断 / 浮窗助理 6 处 = 最多 6 条 TCP 并发连 agent :3113，且各自维护重连/心跳/状态，页面间连接状态chip可能互相矛盾（UI/UX 漂移的根之一）。

**改后**（`useWebSocketData.ts` v4.0）：
- 连接生命周期收敛到**模块级单例控制器**：首个消费者挂载即启动、连接常驻（Layout 恒挂载）；消费者经 `useSyncExternalStore` 订阅同一份不可变快照（6 处消费者 = 1 条连接、1 份状态）。
- 设置驱动语义全部保留且对单例生效（Settings SSOT 订阅）：端点变更**整代重启**（generation 计数使旧代异步回调失效，防串代）；重连间隔/最大次数取设置、超限如实断开；心跳开关/间隔热生效；演示模式关闭时不可达如实断开。
- **dispose 契约**：控制器持有 store 订阅的退订函数，`__resetWebSocketDataControllerForTests()` 先 dispose 再置空——开发中实测：无 dispose 时僵尸控制器会在端点变更时各自重启建连（测试捕获 3 控制器 × 重复连接）。
- 消费者卸载**不再关闭连接**（旧「卸载即断开」用例按新契约反转，注释说明依据）。
- 消息路由/告警三域持久化（跟进工单+日志+操作流）/DataBus 合并逻辑逐行保留。

**测试**：新增 `ws-singleton.test.tsx` 4 例——多消费者单连接 + 快照同引用；node_status 权威快照广播到全部消费者；端点变更旧连接关闭/新端点重连；wsToken 拼接语义保留。既有 54 例全数通过（仅卸载用例反转）。

## 三、矩阵卡 0 值门控铺满（B1 口径收尾）

`Dashboard.tsx` NodeCard：GPU 原有 `gpuAvailable === false → "—"` 门控缺两个洞——①温度**完全不设防**（恒渲染 `{temp}°C` → 全列 0°C 假象）；②旗标缺省（undefined）且值为 0 的旧数据仍显示 `0%`。现统一为与设备性能页/节点详情同口径：

- `gpuNoEvidence = gpuAvailable === false || (undefined && gpu === 0)` → GPU 显示「—」、进度条 0。
- `tempNoEvidence = tempAvailable === false || (undefined && temp === 0)` → 温度显示「—」。

**E2E 实证**（落档 66 契约 G4 四层追溯）：7 节点 GPU 全部「—」（无 DCGM 证据，如实）；`0°C` 渲染计数 **0**；开启真实令牌后首页「已连接」、7/7 活跃节点、延迟 36.9s 与 OpsPanel `/api/metrics/history` 同源同值。
