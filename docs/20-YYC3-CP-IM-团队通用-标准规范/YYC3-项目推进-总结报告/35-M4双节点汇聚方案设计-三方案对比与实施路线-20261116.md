## 一、候选方案

### 方案 A · 前端多 WS 连接（面板直连各节点 agent）

```
面板 node-slice ──WS×N──> yyc3-agent@主控(3113)   [已通]
                   ──WS×N──> yyc3-agent@节点机(3113) [新增：连接管理器]
节点清单来源：系统管理→节点清单（host 可编辑）＝数据源统一
```

- 改动：新增 `useMultiNodeWS`（连接池：按 node-slice user 清单 host 建立 WS，逐连接鉴权令牌、断线重连、快照带 nodeId 归并进 mergeFromWS）；agent 端零改动（已具备 WS+令牌+快照）
- 优点：**零新增后端组件**（符合无后端红线）；改动集中前端一个 hook；节点增减=面板编辑清单即时生效（与「数据源统一系统管理」完全对齐）
- 缺点：N 连接的管理复杂度在前端；浏览器对同域 WS 并发数有隐性上限（≈6/域，跨 host 无碍——节点走 Tailscale IP 各自成域）

### 方案 B · 主控 agent 升级汇聚 hub（agent mesh）

```
节点机 agent ──WS──> 主控 agent(hub 模式) ──单 WS──> 面板
```

- 改动：agent 新增 `--hub` 角色（下游连接表+凭据分发+快照合并+统一推送）；节点 agent 增加 `--upstream` 指向主控
- 优点：前端零改动（单 WS 语义不变）；天然支持节点侧防火墙场景（节点仅出站连接）；后续批量动作（#10）天然落点
- 缺点：agent 复杂度上升（mesh 拓扑/部分失效/时钟漂移）；主控 agent 成单点（KeepAlive 已缓解）；凭据分发需设计

### 方案 C · OpsPanel 中继扩展（Python 侧 WS 推送）

- 改动：OpsPanel 增加 WS 端点把探针/DCGM/vLLM 实时推面板
- 优点：复用已通的探针面；面板只需一个新 WS 客户端
- 缺点：**引入第二实时源**（与 agent 快照双轨，状态归并复杂化）；跨语言双栈维护；违背「agent 为节点数据唯一来源」（落档 20 任务 12 原则）

## 二、评分与推荐（五维加权：达成度 30 / 架构契合 25 / 成本 20 / 风险 15 / 扩展 10）

| 方案 | 达成30 | 契合25 | 成本20 | 风险15 | 扩展10 | 总分 |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| **A 前端多 WS** | 26 | **24** | 17 | 12 | 7 | **86** |
| B agent hub | 28 | 18 | 10 | 9 | 10 | 75 |
| C OpsPanel 中继 | 22 | 12 | 13 | 9 | 6 | 62 |

**推荐：分阶段 A→B**。近期（M4 验收）用 A——两节点直连即可达成 "N/N"，且完全落在既有红线与数据源统一架构上；当节点 ≥5 或需节点侧出站连接/#10 批量动作时演进 B（A 的清单/令牌/归并层全部复用）。C 否决。

## 三、方案 A 实施分解（预计 1~1.5 会话）

| # | 任务 | 验收 |
| ---- | ---- | ---- |
| A1 | node-slice user 清单补 `wsPort`（默认 3113，节点表单可选填） | 表单/类型 |
| A2 | `useMultiNodeWS`：按清单 host 建池（复用 websocket-manager 重连策略；快照打 nodeId 标签归并 mergeFromWS） | 单测：双 mock WS 归并 |
| A3 | 令牌分发：节点机 `~/.yyc3-cloud-matrix/agent-token` 与主控一致（运维手册步骤） | 节点机 healthz |
| A4 | 面板展示：多节点同时上屏（本机 WS 节点 + 远端 WS 节点 + OpsPanel 探针态共存） | **activeNodes="N/N" 浏览器实证** |
| A5 | 断线诚实态：远端 agent 停 → 该节点 inactive（探针兜底） | 实证 |

## 四、风险与对策

| 风险 | 对策 |
| ---- | ---- |
| 浏览器同域 WS 上限 | 节点走各自 Tailscale host（不同源）；>6 节点时启动 B 演进评估 |
| 令牌明文分发 | 自用内网可接受；B 阶段引入每节点独立令牌 |
| 双源状态冲突 | 归并优先级已定：WS 快照 > OpsPanel 探针 > user 维护（现行为保持） |
