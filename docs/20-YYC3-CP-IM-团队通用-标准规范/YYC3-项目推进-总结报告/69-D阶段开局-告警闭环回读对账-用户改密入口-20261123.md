## 一、D 阶段开盘与本批范围

路线（落档 55/57）：数据监控→**告警闭环**→运维闭环→智能引擎。C 阶段（认证/关 Ghost/WS 反代）已由落档 68 收口，本批进入 D：

1. **告警闭环收口**：链路早已接通（前端规则 IDB → `PUT /rules` 下发 → agent 持久化 `~/.yyc3-cloud-matrix/alert-rules.json` → agent 实测 cpu/memory/disk → WS alert 上行 → 跟进/日志/操作流三域落库）。缺的是**回读与对账**——「下发成功」没有 agent 侧证据。本批补齐。
2. **用户改密入口**（落档 68 剩余项清账）：系统管理 → 用户管理每行新增钥匙动作，设置/修改本地登录口令。

## 二、改动

### 1. 回读对账（agent-rules-sync / useAlertRules / AlertRulesPanel）

- `syncAlertRulesToAgent`：PUT 成功后**立即 `GET /rules` 回读**，返回 `localRuleCount / agentRuleCount`；新增 `fetchAgentRules()`。
- `useAlertRules`：`syncState` 状态机（`never / syncing / synced / failed` + 双侧计数 + 时间戳）与 `readbackAgentRules()` 手动对账。
- 面板 chip（`rules-sync-status`）：
  - `已同步 N 条（含回读）`——仅当本地/agent 数量**一致**；
  - `已下发 X 条 · agent 回读 Y 条（数量不一致）`——两侧对不上时如实标注；
  - `未下发 / 未同步：未配置 agent 令牌 / agent 不可达 / http-<code>`——原因逐字呈现，不吞错。

### 2. 用户改密入口（UserManagement）

- 每行钥匙动作（绿=已有口令）→ 弹窗（新口令+确认）→ `hashPassword`（PBKDF2，落档 68 同源）→ `setUserCredentials`；
- 最低强度 ≥6 位、两次一致校验、错误行内呈现；toast 明示「PBKDF2 哈希存储」。

## 三、E2E 实证（探针会话 + agent 实测）

| 步骤 | 结果 |
| ---- | ---- |
| agent 侧预置 1 条规则，面板本地 0 条，点「回读对账」 | chip = **`已下发 0 条 · agent 回读 1 条（数量不一致）`**（如实暴露两侧差异） |
| 清空 agent 规则 → 面板防抖下发 | chip = `已同步 0 条（含回读）` |
| 用户管理 → admin 钥匙 → 设置新口令 | 模态关闭、toast 成功 |
| 旧口令登录 | **「账号或口令不正确」**拒止 |
| 新口令登录 | 进入（`local_` 令牌） |

curl 侧闭环此前已实测：`PUT /rules → {"ok":true,"count":N}` → `GET /rules` 回读一致，agent 落盘文件 `mode 0600`。

## 四、契约符合（落档 66）

G0 全绿（tsc 0E / 282 文件 4743 用例 / build ✓ / lint 0 error）；G2 回执语义：同步状态机即「下行动作的回执」，回读即「回读」；G3：无新路由（复用 agent `/rules` GET/PUT，入落档 68 API 表）；G4：chip 文案逐字可追溯（双侧计数来自真实 PUT/GET）。

## 五、剩余（如实）

- 运维闭环（#10 八动作中节点重启/批量重启/模型部署/迁移/队列 pause-resume 未接）与智能引擎闭环为 D 阶段后续批次。
- Ollama serve 进程当前挂起（/api/tags 超时，属本机运行态，需重启 ollama——主控侧操作）。
- 多用户页面级权限隔离、WS 反代面板侧会话鉴权（需 agent 配合）仍为跨仓库/后续项。
