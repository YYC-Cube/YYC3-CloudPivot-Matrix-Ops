## 一、DGX 现状实勘（规划的设计基础）

| 事实 | 出处 |
| ---- | ---- |
| vLLM = **Docker 容器常驻**：n1 `svl2-head`（:8888，TP2 head）/ n2 `svl2-worker` | dgx-vllm-restart.sh（docker restart 语义，不 kill） |
| **大会话护栏**：`vllm:num_requests_waiting/running > 0` → 拒绝重启 | 同脚本 guard()，可复用为暂停/迁移护栏 |
| 头权重加载 **~60 分钟**（上限 70 分钟 × 20s 轮询） | 同脚本 [3/3] 段 |
| 执行通道 = **plan→confirm 两步确认**（OpsPanel 语义） | 落档 54 #10 批复通道 |
| ssh 免密别名 yyc3-n1/n2 可用；模型在 NVMe；DGX 侧端点（部署/迁移/队列）此前不存在 | 探针实测 + 落档 70 |

## 二、DGX 部署/迁移/队列链路规划（不经 OpsPanel，走 agent actions）

**链路**：面板操作中心（qa2/qa7/qa8/qa9）→ agent `POST /actions/exec {actionId, args}` → 参数白名单校验 → `ACTION_ARG_*` env 注入 → ssh DGX 执行脚本 → 回执（plan/执行结果）→ 面板 toast+日志+history。

**新增四动作**（`~/models/OPS/scripts/dgx/`，sha256 钉扎，plan→confirm 两步——缺 `CONFIRM=destructive-confirm` 时**只输出执行计划，不执行**）：

| 动作 | 语义 | 参数（白名单） | 护栏 |
| ---- | ---- | ---- | ---- |
| `dgx-model-deploy` | docker 起新 vLLM 容器服务新模型 | MODEL（必填，模型目录）/ SERVED_NAME（必填）/ NODE_ALIAS / PORT / GPUS / CONTAINER / CONFIRM | 健康等待 70 分钟上限 |
| `dgx-model-migrate` | 起新→等健康→停旧（drain 切换；旧容器在新健康前不动） | HEALTH_URL（必填）/ NODE_ALIAS / OLD/NEW_CONTAINER / CONFIRM | 新不健康即放弃（旧未动） |
| `dgx-queue-pause` | `docker pause` 服务级冻结（空闲才可暂停） | METRICS_URL（护栏取证）/ NODE_ALIAS / CONTAINER / CONFIRM | **running/waiting>0 拒暂停** |
| `dgx-queue-resume` | `docker unpause` 恢复 | NODE_ALIAS / CONTAINER / CONFIRM | 对称两步 |

**链路所需（DGX 侧前置清单，主控批复后即具备）**：
1. 模型文件放 NVMe 约定目录（如 `/data/models/<name>/`）；
2. 目标端口分配确认（deploy 默认 8899，避免 8888/8002/9400 冲突）；
3. vLLM 容器镜像名确认（脚本内 `<vllm镜像>` 占位需替换为现役镜像——**这是执行前唯一必填项**）；
4. GPU 编号分配（deploy 默认 GPU 0）。

**参数框架**（agent 侧）：动作定义新增 `args` 白名单（key→pattern/required/desc）；`POST /actions/exec` body 支持 `args`；**未知键/超长/不命中 pattern/缺必填一律 400 拒止**（实测：缺 MODEL → `缺少必填参数: MODEL`；CONFIRM=wrong → `参数不合法: CONFIRM`）；通过后映射 `ACTION_ARG_<KEY>` env 注入脚本。**CONFIRM 两步语义**：不传=plan-only（回执持久化执行计划，exit 0）；传 `destructive-confirm` 才实际执行。

## 三、Ollama 常驻 + yyc3-77 同步可识别（已落地）

| 项 | 实现 | 实测 |

| 常驻 | launchd `com.yyc3.ollama`（RunAtLoad + KeepAlive，`deploy/com.yyc3.ollama.plist` 已装 `~/Library/LaunchAgents/`） | PID 88822，`launchctl list` 在册 |

**yyc3-77 接入路径**（数据源页已登记同口径）：yyc3-77 上的应用将 base URL 指向——TS `http://100.87.159.21:11434` 或 LAN `http://192.168.3.22:11434`（两地址均已实测 200）。**安全口径**：Ollama 无鉴权，仅限私网（Tailscale/局域网均为自有设备），符合「数据不出本地」；面板数据源 `src-ollama` 条目已更新为「yyc3-22 常驻 · 跨设备可用」（registry v3 刷新内置说明字段）。
