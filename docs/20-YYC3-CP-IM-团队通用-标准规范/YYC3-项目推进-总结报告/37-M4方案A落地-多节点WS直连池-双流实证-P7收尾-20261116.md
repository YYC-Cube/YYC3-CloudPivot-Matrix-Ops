## 一、M4 方案 A 落地（`9e28290`）

| 分解 | 实现 |
| ---- | ---- |
| A1 wsPort | `NodeData.wsPort?` + NodeEditModal「agent WS 端口」字段（默认 3113，钳制 1-65535） |
| A2 连接池 | `useMultiNodeWS`：按用户清单 host 建池；跳过主端点（**回环归一化** localhost≡127.0.0.1）；断线指数退避（上限 30s）；demoMode/无令牌诚实停用 |
| A5 断线兜底 | 远端 WS 不可达不改状态——OpsPanel 探针兜底（优先级 **WS > 探针 > user** 保持） |
| 归并三保障 | ① 非权威归并（不清他节点）② **大小写 id 归一**（agent 大写主机名 vs 清单小写，防孪生节点）③ **身份字段保留**（source/host/wsPort/role 回填——实证暴露：merge 覆盖丢 source:"user" 后主连接权威合并会清除该节点） |
| 测试 | 3 用例：按清单建连跳主端点 / 远端快照非权威归并 / 无令牌停用（FakeWS 假件） |

## 二、双 WS 流实证（A4 · 3118 浏览器）

**方法**：第二 agent 实例（`PMO_AGENT_PORT=3213 PMO_NODE_ID=YYC3-45`，真实采集进程）+ 清单 yyc3-45 指向 127.0.0.1:3213。

**结果**：主连接(3113→YYC3-22) + 远端连接(3213→YYC3-45) **双流同屏 7/7**；yyc3-45 收到第二 agent 真实快照（gpu 20 / mem 57 / source:"user" 身份保留）——**验收判据达成**（45 无 DCGM 覆盖，gpu/mem>0 只可能来自远端 WS 流）。截图存档。

**排障实录（P3 僵尸页教训再验证）**：首轮 45 被清除=归并丢身份（已修）；二轮 persist 单节点=同源旧页回写竞态，干净单页复验通过。运维提示：同 origin 多标签页共享 localStorage，**验证多 WS 行为时保持单一面板页**。

## 三、真实第二节点接入（运维三步 · 落档 35 A3）

```bash
# 节点机（如 yyc3-n1）：
1. 拷贝 agent/ 目录 → PMO_AGENT_PORT=3113（默认） node yyc3-agent.mjs（或 plist 常驻）
2. 令牌：将主控 ~/.yyc3-cloud-matrix/agent-token 内容写入节点机同路径
3. 面板：数据看盘→编辑节点→host=节点 Tailscale IP（wsPort 默认 3113）→保存
```
