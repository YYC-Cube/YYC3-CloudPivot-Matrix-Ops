## 二、设备矩阵分类 · 新增「性能监控」页

| 项 | 内容 |
| ---- | ---- |
| 分类改名 | `nav.catMonitor`："监控中心" → **"设备矩阵"**（EN: Device Matrix） |
| 新条目 | 「性能监控」（`/device-performance`，`nav.devicePerformance`）——**v1.1 调整为次位**：数据监控（首页 `/`）置首 |
| 概览四卡 | CPU 平均利用率 · 内存平均占用 · GPU 平均利用率 · 最高温度（节点真实数据聚合） |
| 节点性能矩阵 | 每节点 CPU/内存/GPU/温度/功耗 + **每卡 DCGM 明细**（util/temp/power）+ vLLM tok/s |
| 数据源 | 本机 agent WS 快照（CPU/内存/温度）+ OpsPanel `/api/nodes`+`/api/metrics` 探针（10s） |
| 诚实空态 | 无来源指标显示「—」；时序趋势区明确标注「待接入时序存储，不伪造曲线」 |
| 空态动作 | 「从 OpsPanel 导入探针节点」——显式用户动作导入真实清单（**非暗注入**） |

**实证（3118 生产 dist）**：
- 导入后获得 **7 个真实节点**（yyc3-22 主控 M4 Max / yyc3-45 NAS PG双库 / yyc3-33 ECS / yyc3-n1 / yyc3-n2 / yyc3-77 / yyc3-66），6 在线
- yyc3-n1：GPU 95% · 72°C · 44W；yyc3-n2：GPU 95% · 68°C · 39W；vLLM nemotron-3.5-super-vl 27 tok/s
- 每节点角色描述与 Tailscale IP 取自探针（真实）

## 三、红线修复：历史 mock 节点净化

**发现**：实测环境 `yyc3-node-slice` 持久化中含 5 个 mock 节点（`node-a100-01..04`、`node-local-mac`，含 llama-3.3-70b/qwen2.5-72b 假模型名）。源码当前**已无生成点**（DEFAULT_NODES 为空、bundle 无该字符串），属旧版持久化/历史 seed 残留，但会污染性能页与所有节点视图。

**修复（双保险）**：
1. **迁移 v1→v2**：`LEGACY_FAKE_NODE_PATTERNS`（`^node-a100-\d+$`、`^node-local-mac$`）在 migrate 中剔除
2. **运行时净化**：`useNodeSlice.subscribe` 幂等过滤（无论来源，出现即剔除并重算 derived）

**实证**：seed 3 个 mock → 加载后 0 残留、页面进入诚实空态；再导入即真实 7 节点。

## 五、口径

- CPU 口径：本机 agent 的 `node.gpu` 字段上报真实 **CPU 利用率**（agent 内注明，避免误解为 GPU）
- GPU/温度/功耗仅当 OpsPanel DCGM 覆盖该节点时展示；未覆盖显示「—」（不估算）
- 导入探针节点后清单归用户维护（`source: "user"`），WS 权威快照不删除
- 本轮构建曾出现一次**瞬时失败致 dist 清空**（面板 404），重跑即恢复——已确认与代码无关，登记备查
