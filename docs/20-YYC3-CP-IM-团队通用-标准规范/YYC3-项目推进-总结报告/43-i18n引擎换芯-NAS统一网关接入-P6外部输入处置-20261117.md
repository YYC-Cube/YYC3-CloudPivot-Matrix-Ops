## 一、i18n 引擎换芯 @yyc3/i18n-core（`3.6.0`）

**裁定：可以替换，且已完成**——但须澄清：`@yyc3/i18n-core` 是 i18n **框架**（引擎/ICU/插件/OTA），**不携带应用词条包**，zh-CN/en-US 两份 1400 行词典仍在仓内；Mimosa 的 enterApiKey×2 高危提示为 UI 文案误报，换引擎不消除（维持误报登记口径）。

### 1.1 换芯方案（useI18n.ts，52 消费方零改动）

| 项 | 旧实现 | 新实现 |
| ---- | ---- | ---- |
| 词表查找 | 自研 getNestedValue（点分 key） | I18nEngine.t（嵌套 TranslationMap 原生） |
| 模板插值 | 自研 `{n}` 正则 | 引擎 interpolate（ICU 子集，语法兼容） |
| 缺 key 回退 | 返回 key 路径 | missingKeyHandler 返回 key（语义一致） |
| 语言切换 | translations useMemo 重绑 | localeRef → 双引擎选择 |
| 公共 API | useI18n/I18nContext/SUPPORTED_LOCALES | **不变**（52 文件零改动） |

### 1.2 根因链（三轮实证）

1. **首败**：单引擎 + `setLocale`——jsdom 下引擎落 locale 走 `await persistLocale` 异步段，同步渲染流 t() 读旧 locale。
2. **再败**：双引擎各固定 locale——构造非默认 locale（zh-CN ≠ DEFAULT_LOCALE="en"）触发 `loadInitialLocale → void setLocale()` **异步懒加载**，其续体 `state.translations[locale] = 框架自带小语言包`（677B zh-CN chunk）**覆盖已注册的完整词典** → t() 大面积缺 key（注册期探针命中、测试期同引擎 MISS 的分裂现象即此）。
3. **根修**：双引擎均以 `locale: "en"`（DEFAULT_LOCALE）构造——构造器同步短路（`initialLocale === DEFAULT_LOCALE` 直接赋值返回），无异步路径；词典注册在 "en" 标签下**即终态永不覆盖**。语言切换由应用层 localeRef 在两引擎间选择；引擎 locale 语义弃用（仅消费 t()）；LRU 缓存按引擎物理隔离不可能跨语言串味。

### 1.3 门禁

tsc 0 错误；i18n 相关 5 套件 **102/102**；全量 **275 文件 / 4694 用例全绿**（后台首跑曾现 1 例瞬时 teardown error，复跑两次均 0 error，判毛刺不记缺陷）。

### 教训 T-05 · i18n-core 异步懒加载覆盖注册词典

非默认 locale 的引擎构造会 fire-and-forget 懒加载，续体**无条件覆写**该 locale 的 translations（时序在用户 registerTranslation 之后到达）。规避：要么固定 DEFAULT_LOCALE 注册，要么注册后补一次 `setLocale(同locale)` 抬升 generation 使在途回调作废。凡「注册期正确、运行期丢失」的翻译症状，先查该异步覆盖路径。

### 2.1 反代链路（deploy/server.mjs，复刻落档 39 流程）

| 段 | 实现 |
| ---- | ---- |
| 前缀 | `/api/v1/llm/nas/*` → `PMO_NAS_URL`（默认 TS 入口 `100.65.172.88:8000`；公网 `api.0379.world` 同一网关同一把 key） |
| 头翻译 | 面板 provider 统一发 `Authorization: Bearer <vk>` → 代理层改写为 `X-API-Key: <vk>` 上送（NAS 网关只认 X-API-Key；翻译仅在无显式 X-API-Key 时进行） |
| 模型 | `cm-nas-001`：providerId custom · model `nemotron-3.5-super-vl` · **baseUrl `v1`（相对段）** · proxyUrl `http://localhost:3118/api/v1/llm/nas` |

### 2.2 实证（三级）

1. **直连**：TS 网关 `/v1/models` 200（11 模型目录）；`/v1/chat/completions` 200，nemotron 真实回复（`vllm-0.32.0-tp2` 指纹）。
2. **反代**：`/api/v1/llm/nas/v1/models` 200 + chat 200（Bearer→X-API-Key 翻译生效，回复「收到」）。
3. **面板 E2E**（独立 headless profile 种子 persist，不触用户配置）：`#/ai-family/chat` 发言 → `200 POST …/nas/v1/chat/completions` → **天枢/守护双成员带人格真实回复**（「我是天枢，走内网专线链路」「我是守护，走安全加密链路」）。

### 教训 T-06 · buildChatUrl 相对 baseUrl 契约

`buildChatUrl`：`proxy + "/" + baseUrl + "/chat/completions"`——baseUrl 必须是**相对段**（如 `v1`），由 proxy 前缀映射上游根；填绝对 URL 会拼出 `…/nas/http://100.65.172.88:8000/v1/chat/completions` 路径形态 → 上游 404（本次实证踩中，DGX 接入同契约）。另：provider-slice persist **version=0**（无版本迁移），种子/迁移脚本必须按 0 写。

## 四、#13 内容包需求规格（已明确）

**交付物**：一个 JSON 包（envelope 与 ConfigExportCenter 兼容）+ 可选 artworks 目录。**模板已内置**：[public/templates/ai-family-content-pack.template.json](../../../public/templates/ai-family-content-pack.template.json)（经 `面板 → 系统管理 → 配置中心 → 导入` 投放）。

| 域 | 内容 | 约束 |
| ---- | ---- | ---- |
| posts / activities / memories / skills | 家庭动态/活动/记忆/技能条目 | memberId ∈ 八成员枚举；ISO8601 时间；content ≤2000 字 |
| settings（子集） | 称号/格言/主题色等展示类 | **模型绑定与密钥字段拒收**（凭据卫生红线） |
| artworks | 作品图片（fun artworks 替换通道） | 单文件 ≤2MB · 包总 ≤50MB |
| import | mergeMode（skipExisting/upsert）+ dryRun | dryRun 预览「导入 N / 跳过 M」清单 |

**验收六条**：packId 全局唯一；memberId 枚举合法；ISO8601；体积限额；settings 含模型/密钥字段整包拒收；dryRun 预览。**剩余输入 = 用户按模板填充内容本体**（导入器实现随下批代码）。

## 五、8 位成员云端 key 处置（转按需自配置）

主控口径：成员模型**可自定义/自编辑/选择**（本地 Ollama、自定义 baseUrl 如 NAS/DGX、云端预设）。核验：`#/ai-family/models` 逐成员绑定编辑（provider/model/baseUrl/apiKey/三步诊断）+ 群聊 getActiveModel 路径均已具备且实证（NAS 群聊真实往返即走 cm 模型）。**结论：不再等云端 key 批量输入**——云端成员各 key 到位后经同 UI 自助激活；本地链路（Ollama/DGX/NAS）现已全通。
