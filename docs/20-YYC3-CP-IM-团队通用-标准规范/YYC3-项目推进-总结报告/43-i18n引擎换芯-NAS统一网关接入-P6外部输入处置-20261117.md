## 一、i18n 引擎换芯 @yyc3/i18n-core（`3.6.0`）

**裁定：可以替换，且已完成**——但须澄清：`@yyc3/i18n-core` 是 i18n **框架**（引擎/ICU/插件/OTA），**不携带应用词条包**，zh-CN/en-US 两份 1400 行词典仍在仓内；Mimosa 的 enterApiKey×2 高危提示为 UI 文案误报，换引擎不消除（维持误报登记口径）。

### 1.1 换芯方案（useI18n.ts，52 消费方零改动）

| 项 | 旧实现 | 新实现 |
| ---- | ---- | ---- |
| 词表查找 | 自研 getNestedValue（点分 key） | I18nEngine.t（嵌套 TranslationMap 原生） |
| 模板插值 | 自研 `{n}` 正则 | 引擎 interpolate（ICU 子集，语法兼容） |
| 缺 key 回退 | 返回 key 路径 | missingKeyHandler 返回 key（语义一致） |
| 语言切换 | translations useMemo 重绑 | localeRef → 双引擎选择 |
| 公共 API | useI18n/I18nContext/SUPPORTED_LOCALES | **不变**（52 文件零改动） |

### 1.2 根因链（三轮实证）

1. **首败**：单引擎 + `setLocale`——jsdom 下引擎落 locale 走 `await persistLocale` 异步段，同步渲染流 t() 读旧 locale。
2. **再败**：双引擎各固定 locale——构造非默认 locale（zh-CN ≠ DEFAULT_LOCALE="en"）触发 `loadInitialLocale → void setLocale()` **异步懒加载**，其续体 `state.translations[locale] = 框架自带小语言包`（677B zh-CN chunk）**覆盖已注册的完整词典** → t() 大面积缺 key（注册期探针命中、测试期同引擎 MISS 的分裂现象即此）。
3. **根修**：双引擎均以 `locale: "en"`（DEFAULT_LOCALE）构造——构造器同步短路（`initialLocale === DEFAULT_LOCALE` 直接赋值返回），无异步路径；词典注册在 "en" 标签下**即终态永不覆盖**。语言切换由应用层 localeRef 在两引擎间选择；引擎 locale 语义弃用（仅消费 t()）；LRU 缓存按引擎物理隔离不可能跨语言串味。

### 教训 T-05 · i18n-core 异步懒加载覆盖注册词典

非默认 locale 的引擎构造会 fire-and-forget 懒加载，续体**无条件覆写**该 locale 的 translations（时序在用户 registerTranslation 之后到达）。规避：要么固定 DEFAULT_LOCALE 注册，要么注册后补一次 `setLocale(同locale)` 抬升 generation 使在途回调作废。凡「注册期正确、运行期丢失」的翻译症状，先查该异步覆盖路径。

### 教训 T-06 · buildChatUrl 相对 baseUrl 契约

`buildChatUrl`：`proxy + "/" + baseUrl + "/chat/completions"`——baseUrl 必须是**相对段**（如 `v1`），由 proxy 前缀映射上游根；填绝对 URL 会拼出 `…/nas/http://100.65.172.88:8000/v1/chat/completions` 路径形态 → 上游 404（本次实证踩中，DGX 接入同契约）。另：provider-slice persist **version=0**（无版本迁移），种子/迁移脚本必须按 0 写。
