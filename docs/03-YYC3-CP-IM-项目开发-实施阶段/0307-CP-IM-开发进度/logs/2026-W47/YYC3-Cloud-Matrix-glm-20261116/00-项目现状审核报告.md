## 二、深度维度分析

### 2.1 架构合理性

**现状**：分层清晰——采集（agent）→ 传输（WS + IPC）→ 状态（Zustand 三套）→ 页面（42 路由 lazy）→ 构建（Vite 手动分包 + 门禁 CI）。Electron 安全基线正确（nodeIntegration:false / contextIsolation:true / CSP / 窗口拦截）。

**问题**：① Zustand 三套并存（`store/slices` 17 + `ai-family/store` 14 + `stores/` legacy），状态层双源；② Supabase 出现在 18 个文件但生产实为 Mock，数据层叙事与实现不一致；③ `src/shared/ipc-types.js` 编译产物误入库；④ `ide/`（405 个被跟踪文件）为未接线的孤立副本工程，与 `modules/dev/ide/` 双源并存。

**影响**：状态双源增加排障与二开成本；数据层「假 Supabase」误导新成员与外部协作者；孤立树拖慢全仓检索、lint 与依赖升级。

### 2.2 代码质量

**现状**：门禁体系完整（tsc 0 错误、ESLint 0 错误 4 警告、vitest 5063 用例、覆盖率棘轮 45/44/31/44、TODO/FIXME≈0、真实 console.log≈0），质量纪律明显高于同类项目。

**问题**：① `FamilyActivityCenter.test.tsx` 16 用例失败（工作区未提交的真实化改动删了「8T」假文案，测试未同步）；② `: any` 155 处，`electron/tsconfig` 显式 `strict:false`；③ 最大单文件 1460 行（`SystemSettings.tsx`），千行级文件 10 个。

**影响**：当前 main 合并即带红测试（若 CI 在 push 时同样失败，说明存在绕过门禁提交的通道）；any 泛滥削弱 TS 价值；巨型文件为后续改动高风险区。

### 2.3 技术债务

**现状**：债务集中在依赖与基建层，业务代码刚完成 06→21 十轮「真实化」治理。

**问题**：① 零使用死重依赖：`@mui/material`+`@mui/icons-material`+`@emotion/*`+`@popperjs/core`+`react-dnd`+`react-dnd-html5-backend`+`react-slick`+`react-responsive-masonry`+`immer`+`date-fns`；② `react-router` 与 `react-router-dom` 双装且版本漂移（7.18 vs 7.14）；③ `lucide-react@^1.8.0` 疑似虚构版本号；④ package.json 引用的 6 个脚本文件全部不存在（`check-headers.js`、`add-header.js`、`setup-git-hooks.sh`、`check-testid-naming.js`、`fix-testid-prefix.js`、`fix-all-testids.js`）→ `precommit` 链第一步即断；⑤ e2e 5 个 spec 无运行器接管（playwright 配置 defineConfig 被注释、无根级配置、baseURL 硬编码内网 IP）；⑥ `src/database/` 9 文件零测试；⑦ 工作区中间态未收口（66 删除 + 31 未跟踪 + 14 修改）。

**影响**：安装体积与攻击面无谓增大；依赖升级与安全审计被噪音干扰；本地提交门禁实际失效。

### 2.4 性能风险

**现状**：路由级懒加载 + manualChunks；构建 1.12s 完成；agent 10s 节流采集。

**问题**：① `react-vendor` 1.61MB、`vendor` 391KB、`index` 385KB，首包超 600KB 警戒线；② localStorage 作为权威持久层（31 键），无配额与损坏恢复策略文档；③ 无接口级性能基准（Lighthouse CI 配置存在但未见持续运行证据）。

**影响**：首屏加载在弱网/低端机劣化；大数据量下 localStorage 写入阻塞主线程；性能回归无门禁拦截。

### 2.5 安全风险

**现状**：无硬编码真实密钥（扫描仅命中占位与测试夹具）；.env 已忽略且不入库；CSP 生产态收紧至 self + `*.supabase.co`；audit 阶 critical 门禁。

**问题**：① preload 暴露面过宽：`yyc3.shell.execute`（任意命令）、`yyc3.database.execute`（原始 SQL）、全套文件 CRUD，参数全 `any` 无白名单；② Ghost 登录为免凭证全权限 admin（有意设计，但桌面分发后即成后门）；③ Mock 用户密码经 `VITE_MOCK_*` 环境变量进入客户端包（VITE_ 前缀变量会被打包公开）；④ `deploy/com.yyc3.agent.plist` 将 agent 绑定 `0.0.0.0`（靠令牌保护，暴露面仍在）；⑤ `pnpm audit` 仅拦 critical，high 放行。

**影响**：任一渲染进程 XSS 即可升级为宿主机任意命令执行；对外分发版本必须提供禁用 Ghost 登录的构建开关。

### 2.6 可维护性

**现状**：文档体系庞大（docs/ 00~16 阶段 + 20 标规 + modules/tests 三层，约 800+ 文档）、CONTRIBUTING/SECURITY 齐备、CI 自解释性好。

**问题**：① docs/README.md 统计与索引滞后（引用已删文件、目录数 14→实际 17），文档标头完整率自报 23.0%、命名规范 0.7%；② 双部署域名表述不一致（CI CNAME `matrix.yyc3.vip` vs CHANGELOG/README `matrix.yyc3.top`）；③ Electron 产物路径与 package.json `main` 错位（见 P0）；④ 会话文档无统一日志制度（本次已建立，见 006-总纲）。

**影响**：新协作者上手成本高；部署排障时域名/路径歧义直接浪费时间。

### 3.3 边界与异常场景清单
